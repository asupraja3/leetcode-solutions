Real Karat Style

How Karat Analysis works: They show you a code snippet and ask: "What does this output?", "Is there a bug?", "What's the performance issue?", or "How would you improve this for production?" You read, reason, and explain verbally. No coding needed — just analysis and communication.

OUTPUT

1. "What does this print?"

01Mutable default argument+
def add_item(item, lst=[]):
    lst.append(item)
    return lst

print(add_item(1))
print(add_item(2))
print(add_item(3))
Output 
[1]
[1, 2]
[1, 2, 3]
Why

The default [] is created once at function definition. All calls share the same list object. Each call appends to it.

Fix

Use None as default: def add_item(item, lst=None): if lst is None: lst = []

CLASSIC KARAT QUESTION

02List aliasing vs copy+
a = [1, 2, 3]
b = a
b.append(4)
print(a)
print(a is b)
Output 
[1, 2, 3, 4]
True

b = a creates a reference, not a copy. Both point to the same list. b = a.copy() or b = a[:] would create an independent copy.

03Late binding closure in loop+
funcs = []
for i in range(4):
    funcs.append(lambda: i)

print([f() for f in funcs])
Output 
[3, 3, 3, 3]

Closures capture the variable i, not its value. By loop end, i is 3 for all. Fix: lambda i=i: i (default arg captures current value).

04Integer caching / interning+
a = 256
b = 256
print(a is b)

c = 257
d = 257
print(c is d)
Output 
True
False  (usually, implementation-dependent)

CPython caches integers -5 to 256. a is b is True because they reference the same cached object. 257 is outside the cache, so c and d are different objects. Never use is for value comparison — use ==.

05String multiplication and mutability+
s = "hello"
s[0] = "H"
print(s)
Output 
TypeError: 'str' object does not support item assignment

Strings are immutable. You can't change characters in-place. Fix: s = "H" + s[1:]

06Dictionary iteration and modification+
d = {"a": 1, "b": 2, "c": 3}
for key in d:
    if d[key] % 2 == 0:
        del d[key]
Output 
RuntimeError: dictionary changed size during iteration

Can't modify dict while iterating. Fix: iterate over a copy of keys: for key in list(d.keys()):

07Tuple unpacking surprise+
x = (1)
y = (1,)
print(type(x), type(y))
Output 
<class 'int'> <class 'tuple'>

(1) is just parenthesized integer. You need the trailing comma (1,) to make a single-element tuple.

08List multiplication trap+
grid = [[0] * 3] * 3
grid[0][0] = 1
print(grid)
Output 
[[1, 0, 0], [1, 0, 0], [1, 0, 0]]

[[0]*3] * 3 creates 3 references to the same inner list. Changing one changes all. Fix: [[0]*3 for _ in range(3)]

VERY COMMONLY ASKED

09Global vs local scope+
x = 10
def foo():
    x = x + 1
    return x
print(foo())
Output 
UnboundLocalError: local variable 'x' referenced before assignment

Assignment to x makes it local, but x + 1 reads it before assignment. Fix: use global x or pass as parameter.

10Chained comparison+
print(1 < 2 < 3)
print(1 < 2 > 0)
print(1 == 1.0 == True)
Output 
True
True
True

Python chains comparisons: 1 < 2 < 3 means 1 < 2 and 2 < 3. True == 1 == 1.0 because bool is a subclass of int.

11Dictionary comprehension overwrite+
d = {k: v for k, v in [(1, 'a'), (2, 'b'), (1, 'c')]}
print(d)
Output 
{1: 'c', 2: 'b'}

Duplicate key 1 — last value wins. Same behavior as dict constructor.

12or/and return values (not just booleans)+
print(0 or "" or [] or "hello" or 42)
print(1 and "yes" and [] and "no")
Output 
hello
[]

or returns the first truthy value. and returns the first falsy value (or the last if all truthy). They return the actual object, not True/False.

13Nested list shallow copy+
import copy
a = [[1, 2], [3, 4]]
b = copy.copy(a)
b[0].append(99)
print(a)
Output 
[[1, 2, 99], [3, 4]]

Shallow copy creates new outer list but inner lists are still shared references. Use copy.deepcopy(a) for full independence.

14Class variable vs instance variable+
class Dog:
    tricks = []
    def add_trick(self, trick):
        self.tricks.append(trick)

d1 = Dog()
d2 = Dog()
d1.add_trick("roll over")
print(d2.tricks)
Output 
['roll over']

tricks is a class variable — shared across all instances. Fix: define in __init__: self.tricks = []

FREQUENTLY ASKED

15Generator exhaustion+
gen = (x for x in range(3))
print(list(gen))
print(list(gen))
Output 
[0, 1, 2]
[]

Generators can only be iterated once. After exhaustion, calling list() returns empty. If you need multiple passes, use a list or recreate the generator.

BUG

2. "Find the Bug in This Code"

16Silent exception swallowing+
def get_user(user_id):
    try:
        user = db.query(f"SELECT * FROM users WHERE id={user_id}")
        return user
    except:
        pass
Bugs (Multiple!)

1. Bare except: pass — silently swallows ALL errors including KeyboardInterrupt, SystemExit. Bugs become invisible.

2. SQL injection — f-string interpolation in SQL. User could pass "1; DROP TABLE users".

3. Returns None implicitly on exception — caller might get NoneType errors later.

Fix 
def get_user(user_id):
    try:
        user = db.query(
            "SELECT * FROM users WHERE id = %s", (user_id,)
        )  # parameterized query
        return user
    except DatabaseError as e:
        logger.error(f"DB error for user {user_id}: {e}")
        raise
17Off-by-one in range+
def get_pairs(lst):
    pairs = []
    for i in range(len(lst)):
        pairs.append((lst[i], lst[i+1]))
    return pairs

print(get_pairs([1, 2, 3, 4]))
Bug

IndexError on last iteration: lst[i+1] when i = len(lst)-1 is out of bounds.

Fix

for i in range(len(lst) - 1) or pythonically: list(zip(lst, lst[1:]))

18Modifying list while iterating+
numbers = [1, 2, 3, 4, 5, 6]
for num in numbers:
    if num % 2 == 0:
        numbers.remove(num)
print(numbers)
Output (Unexpected!) 
[1, 3, 5]  # Looks correct but...
# With [1,2,3,4,5,6,7,8] → [1,3,5,7] misses 4!

Removing during iteration shifts indices — some elements get skipped. Fix: iterate over a copy for num in numbers[:]: or use list comprehension [n for n in numbers if n % 2 != 0].

19Equality vs identity for None check+
def process(data=None):
    if data == None:
        data = []
    # ... process data
Bug

Using == instead of is for None check. == can be overridden by custom __eq__ — objects could falsely equal None. Fix: if data is None:

20File handle leak+
def read_config(path):
    f = open(path)
    config = json.load(f)
    return config
Bug

File never closed. If json.load raises an exception, the file handle leaks. Fix: use context manager with open(path) as f:

21Boolean comparison anti-pattern+
if active == True:
    do_something()
if items != []:
    process(items)
Issues

1. if active == True → just if active:. 2. if items != [] → just if items:. Empty collections are falsy in Python. Explicit comparison is redundant and can break with subclasses.

22Variable shadowing built-in+
list = [1, 2, 3]
dict = {"a": 1}
# ... later in code ...
new_list = list(range(5))
Output 
TypeError: 'list' object is not callable

Naming variables list, dict, str, type, id, input shadows the built-in. Now list refers to the [1,2,3] object, not the constructor. Never shadow built-ins.

23Circular import+
# module_a.py
from module_b import func_b
def func_a(): return func_b()

# module_b.py
from module_a import func_a
def func_b(): return func_a()
Bug

Circular import → ImportError or partially initialized module. Fix: restructure to remove cycle, use lazy imports inside functions, or create a third module for shared code.

24Integer division surprise (Python 2 vs 3)+
# Someone migrated from Python 2
result = 7 / 2
print(result)

result2 = 7 // 2
print(result2)
Output (Python 3) 
3.5
3

In Python 3, / is true division (returns float). // is floor division (returns int). In Python 2, 7/2 was 3. Know this for migrated codebases.

25Unpacking wrong number of values+
data = [("Alice", 25, "NYC"), ("Bob", 30)]
for name, age, city in data:
    print(f"{name} from {city}")
Bug

Second tuple has only 2 elements → ValueError: not enough values to unpack. Fix: validate data first, use try/except, or use *rest unpacking: name, age, *rest = row

PERFORMANCE

3. "What's the Performance Issue?"

26String concatenation in loop — O(n²)+
def build_report(items):
    result = ""
    for item in items:  # 100K items
        result += f"Item: {item}\n"
    return result
Issue

Strings are immutable. Each += creates a new string and copies all previous content. For n items: O(n²) time, O(n²) total allocations.

Fix 
def build_report(items):
    parts = []
    for item in items:
        parts.append(f"Item: {item}")
    return "\n".join(parts)  # O(n)

#1 MOST ASKED PERFORMANCE Q

27List membership check — O(n) per lookup+
def find_common(list1, list2):
    common = []
    for item in list1:       # O(n)
        if item in list2:    # O(m) per check!
            common.append(item)
    return common
Issue

Total: O(n × m). For 100K items each = 10 billion operations.

Fix 
def find_common(list1, list2):
    set2 = set(list2)  # O(m) once
    return [item for item in list1 if item in set2]  # O(n)

28Repeated expensive computation+
def get_recommendations(user_ids):
    results = []
    for uid in user_ids:
        prefs = fetch_user_preferences(uid)  # DB call
        popular = get_popular_items()  # Same expensive call every iteration!
        results.append(match(prefs, popular))
    return results
Issue

get_popular_items() is called N times but returns the same data. Move it outside the loop, or cache with @lru_cache.

29Loading entire file into memory+
def process_log(filename):
    with open(filename) as f:
        lines = f.readlines()  # Loads ALL lines into memory
    for line in lines:
        if "ERROR" in line:
            print(line)
Issue

For a 10GB log file, this loads everything into RAM. OOM crash.

Fix 
def process_log(filename):
    with open(filename) as f:
        for line in f:  # Streams line by line, O(1) memory
            if "ERROR" in line:
                print(line)
30Nested loop that could be a hash lookup+
def find_duplicates(list1, list2):
    dupes = []
    for a in list1:        # O(n)
        for b in list2:    # O(m)
            if a == b:
                dupes.append(a)
    return dupes
Issue

O(n × m) brute force. Fix: return list(set(list1) & set(list2)) → O(n + m).

31Sorting when you only need min/max+
def get_top_scorer(students):
    sorted_students = sorted(students, key=lambda s: s.score, reverse=True)
    return sorted_students[0]
Issue

Sorting is O(n log n) just to find one element. max(students, key=lambda s: s.score) is O(n). For top-k, use heapq.nlargest(k, students, key=...) → O(n log k).

32Pandas apply with Python function+
df['result'] = df['value'].apply(lambda x: x ** 2 + 2 * x + 1)
Issue

apply with a Python lambda iterates row-by-row — no vectorization benefit. For numerical ops, use vectorized: df['result'] = df['value']**2 + 2*df['value'] + 1. Can be 100x faster.

33Creating objects in a hot loop+
import re
def validate_emails(emails):
    valid = []
    for email in emails:  # 1M emails
        pattern = re.compile(r'^[\w.-]+@[\w.-]+\.\w+$')
        if pattern.match(email):
            valid.append(email)
    return valid
Issue

Regex is recompiled on every iteration. Move re.compile() outside the loop — compile once, use many times.

34Recursive fibonacci without memoization+
def fib(n):
    if n <= 1:
        return n
    return fib(n-1) + fib(n-2)
Issue

O(2^n) time — recalculates same values exponentially. fib(50) would take years.

Fix

Add @functools.lru_cache → O(n). Or use iterative approach with two variables.

35Using list.insert(0, x) repeatedly+
def build_reversed(items):
    result = []
    for item in items:
        result.insert(0, item)  # O(n) each time!
    return result
Issue

list.insert(0, x) shifts all elements → O(n) per call. Total O(n²). Fix: use collections.deque with appendleft() → O(1), or just result.append(item) and result.reverse() at the end.

SECURITY

4. "Is This Production-Ready? What's Dangerous?"

36SQL injection via f-string+
def get_user(username):
    query = f"SELECT * FROM users WHERE name = '{username}'"
    return db.execute(query)
Vulnerability

If username = "'; DROP TABLE users; --" → SQL injection. Always use parameterized queries: db.execute("SELECT * FROM users WHERE name = %s", (username,))

37Using eval() on user input+
def calculate(expression):
    return eval(expression)

# User sends: "__import__('os').system('rm -rf /')"
Vulnerability

eval() executes arbitrary Python code. Never use on untrusted input. Use ast.literal_eval() for safe literal parsing, or a proper expression parser.

38Hardcoded secrets+
API_KEY = "sk-abc123secretkey456"
DB_PASSWORD = "admin123"

def connect():
    return psycopg2.connect(password=DB_PASSWORD)
Issue

Secrets in source code get committed to git. Fix: use environment variables (os.environ["API_KEY"]), .env files (never committed), or secrets managers (AWS Secrets Manager, Azure Key Vault).

39Pickle deserialization of untrusted data+
import pickle
data = pickle.loads(user_uploaded_bytes)
Vulnerability

Pickle can execute arbitrary code during deserialization. Never unpickle data from untrusted sources. Use JSON, MessagePack, or protobuf for untrusted data.

40Logging sensitive data+
def login(username, password):
    logger.info(f"Login attempt: {username}, password: {password}")
    return authenticate(username, password)
Issue

Passwords in logs! Anyone with log access sees credentials. Never log passwords, tokens, PII, credit card numbers. Log only: username, timestamp, success/failure status.

41No input validation on API+
@app.post("/predict")
def predict(data: dict):
    features = data["features"]
    return model.predict([features])
Issues

1. No type validation — features could be anything. 2. No bounds checking. 3. KeyError if "features" missing. Fix: use Pydantic models with FastAPI for automatic validation and type checking.

42Debug mode in production+
if __name__ == "__main__":
    app.run(debug=True, host="0.0.0.0")
Issue

debug=True in production exposes: interactive debugger (code execution!), full stack traces with source code, auto-reloader. Never run debug mode in prod. Use debug=False and a production WSGI server (gunicorn, uvicorn).

CONCURRENCY

5. Concurrency & Async Analysis

43Race condition with shared state+
import threading
counter = 0

def increment():
    global counter
    for _ in range(1000000):
        counter += 1

t1 = threading.Thread(target=increment)
t2 = threading.Thread(target=increment)
t1.start(); t2.start()
t1.join(); t2.join()
print(counter)  # Expected: 2000000
Actual Output

Less than 2000000 (varies). counter += 1 is NOT atomic — it's read-modify-write. Threads can interleave. Fix: use threading.Lock(), or queue.Queue, or avoid shared mutable state.

44Blocking call in async function+
import asyncio, time

async def fetch_data():
    time.sleep(3)  # BLOCKING!
    return "data"

async def main():
    results = await asyncio.gather(
        fetch_data(), fetch_data(), fetch_data()
    )
    print(results)
Issue

time.sleep() blocks the entire event loop — tasks run sequentially (9 seconds total). Use await asyncio.sleep(3) for non-blocking. For real I/O, use async libraries (aiohttp, asyncpg).

45Threading for CPU-bound work+
from concurrent.futures import ThreadPoolExecutor
import math

def heavy_computation(n):
    return sum(math.factorial(i) for i in range(n))

with ThreadPoolExecutor(max_workers=4) as pool:
    results = list(pool.map(heavy_computation, [1000]*4))
Issue

Using threads for CPU-bound work. Due to GIL, only one thread runs Python at a time — no speedup. Fix: ProcessPoolExecutor for true parallelism.

46Deadlock potential+
lock_a = threading.Lock()
lock_b = threading.Lock()

def task1():
    with lock_a:
        time.sleep(0.1)
        with lock_b:  # Waits for lock_b
            print("Task 1")

def task2():
    with lock_b:
        time.sleep(0.1)
        with lock_a:  # Waits for lock_a
            print("Task 2")
Issue

Classic deadlock: task1 holds lock_a, waits for lock_b. task2 holds lock_b, waits for lock_a. Neither can proceed. Fix: always acquire locks in the same order, or use threading.RLock() or timeout.

REFACTOR

6. "How Would You Improve This Code?"

47Nested if-else pyramid+
def get_discount(user):
    if user.is_premium:
        if user.years > 5:
            if user.orders > 100:
                return 0.3
            else:
                return 0.2
        else:
            return 0.1
    else:
        return 0
Improved 
def get_discount(user):
    if not user.is_premium:
        return 0
    if user.years > 5 and user.orders > 100:
        return 0.3
    if user.years > 5:
        return 0.2
    return 0.1

Use early returns (guard clauses) to flatten nesting. Each return handles one case and exits. Much more readable.

48Repeated code (DRY violation)+
def process_csv(filename):
    f = open(filename)
    data = csv.reader(f)
    results = []
    for row in data:
        results.append(row[0].strip().lower())
    f.close()
    return results

def process_tsv(filename):
    f = open(filename)
    data = csv.reader(f, delimiter='\t')
    results = []
    for row in data:
        results.append(row[0].strip().lower())
    f.close()
    return results
Improved 
def process_file(filename, delimiter=','):
    with open(filename) as f:
        return [row[0].strip().lower()
                for row in csv.reader(f, delimiter=delimiter)]

Combine into one function with a parameter. Also: context manager, list comprehension, less code = fewer bugs.

49Magic numbers and unclear naming+
def calc(d, r):
    if d > 30:
        return d * r * 0.85
    elif d > 10:
        return d * r * 0.92
    return d * r
Improved 
BULK_DISCOUNT = 0.85
MEDIUM_DISCOUNT = 0.92
BULK_THRESHOLD = 30
MEDIUM_THRESHOLD = 10

def calculate_price(quantity, unit_rate):
    if quantity > BULK_THRESHOLD:
        return quantity * unit_rate * BULK_DISCOUNT
    if quantity > MEDIUM_THRESHOLD:
        return quantity * unit_rate * MEDIUM_DISCOUNT
    return quantity * unit_rate

Named constants, descriptive variable names, self-documenting code.

50Manual dict counting → Counter+
def count_words(text):
    counts = {}
    for word in text.split():
        if word in counts:
            counts[word] += 1
        else:
            counts[word] = 1
    return counts
Improved 
from collections import Counter
def count_words(text):
    return Counter(text.split())

One line. Built-in, optimized, gives you .most_common(n) for free.

51Manual loop → list comprehension+
result = []
for i in range(len(items)):
    if items[i].active:
        result.append(items[i].name.upper())
Improved 
result = [item.name.upper() for item in items if item.active]

More Pythonic, faster (C-optimized loop internally), no index variable needed. Never use range(len(...)) when you can iterate directly.

52Type checking with isinstance vs type+
def process(data):
    if type(data) == list:
        return sum(data)
    elif type(data) == dict:
        return sum(data.values())
Improved 
def process(data):
    if isinstance(data, list):
        return sum(data)
    elif isinstance(data, dict):
        return sum(data.values())

isinstance() respects inheritance — a subclass of list would fail type() == list but pass isinstance(). Also supports tuples: isinstance(x, (list, tuple)).

53Multiple return values → namedtuple+
def analyze(data):
    return len(data), sum(data)/len(data), max(data), min(data)

count, avg, mx, mn = analyze(numbers)  # What's what?
Improved 
from collections import namedtuple
Stats = namedtuple('Stats', ['count', 'average', 'maximum', 'minimum'])

def analyze(data):
    return Stats(len(data), sum(data)/len(data), max(data), min(data))

result = analyze(numbers)
print(result.average)  # Self-documenting!
54Verbose try/except for key access+
try:
    value = config["database"]["host"]
except KeyError:
    value = "localhost"
Improved 
value = config.get("database", {}).get("host", "localhost")

Chained .get() with defaults. Even better for deep access: use a helper or dict.setdefault().

55God function doing too much+
def process_order(order):
    # Validate (20 lines)
    # Calculate total (15 lines)
    # Apply discount (10 lines)
    # Charge payment (20 lines)
    # Send confirmation email (15 lines)
    # Update inventory (10 lines)
    # Log analytics (5 lines)
    pass  # 95+ lines
Improved

Break into single-responsibility functions: validate_order(), calculate_total(), apply_discount(), charge_payment(), send_confirmation(), update_inventory(). Each testable independently.

This shows understanding of SOLID principles — Single Responsibility in particular.

56Using global state in ML pipeline+
model = None

def load_model():
    global model
    model = pickle.load(open("model.pkl", "rb"))

def predict(features):
    if model is None:
        load_model()
    return model.predict(features)
Issues

1. Global mutable state — not thread-safe. 2. File handle leak. 3. No error handling. 4. Hard to test (can't inject different models).

Improved

Use a class: ModelService with __init__ loading the model. Or dependency injection. Or FastAPI's app.state. Context manager for file. Try/except for load failures.

57Catching too broad an exception+
try:
    data = json.loads(raw_input)
    result = data["key"] / data["divisor"]
    save_to_db(result)
except Exception as e:
    return {"error": "Something went wrong"}
Improved 
try:
    data = json.loads(raw_input)
except json.JSONDecodeError:
    return {"error": "Invalid JSON format"}
try:
    result = data["key"] / data["divisor"]
except KeyError as e:
    return {"error": f"Missing field: {e}"}
except ZeroDivisionError:
    return {"error": "Divisor cannot be zero"}
save_to_db(result)

Separate try blocks, specific exceptions, useful error messages. Users and developers can both understand what went wrong.

58Hardcoded paths and config+
def load_data():

    return df, pickle.load(open(model_path, "rb"))

59No type hints on API functions+
def transform(data, config, flag):
    if flag:
        return [config["fn"](x) for x in data]
    return data
Improved 
from typing import Callable, Any

def transform(
    data: list[float],
    config: dict[str, Callable],
    apply_transform: bool
) -> list[float]:
    if apply_transform:
        return [config["fn"](x) for x in data]
    return data

Type hints + descriptive param name (apply_transform vs flag). IDE helps you, mypy catches bugs, new team members understand instantly.

60API endpoint without proper error handling+
@app.post("/analyze")
def analyze(request):
    text = request.json["text"]
    embeddings = model.encode(text)

Improved 
from pydantic import BaseModel
from fastapi import HTTPException

class AnalyzeRequest(BaseModel):
    text: str
    k: int = 5

@app.post("/analyze")
async def analyze(req: AnalyzeRequest):
    try:
        embeddings = model.encode(req.text)
        similar = await vector_db.search(embeddings, k=req.k)
        return {"results": similar}
    except ModelError as e:
        raise HTTPException(status_code=503, detail="Model unavailable")
    except VectorDBError as e:
        raise HTTPException(status_code=502, detail="Search failed")

Pydantic validation, async, proper HTTP error codes, specific exception handling. Production-ready.
