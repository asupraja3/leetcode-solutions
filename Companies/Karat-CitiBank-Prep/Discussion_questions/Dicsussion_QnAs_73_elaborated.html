1. Core Python Fundamentals

01What is the GIL? How does it affect multithreading?+
Answer

The GIL (Global Interpreter Lock) is a lock built into CPython that allows only one thread to execute Python bytecode at a time, even on a multi-core CPU. It exists because Python tracks memory using reference counting (every object has a counter of how many variables point to it), and without the GIL, two threads could corrupt those counters simultaneously.

Impact: If your code is CPU-bound (doing heavy computation like number crunching or ML training), multithreading won't give you real parallelism — threads just take turns instead of running simultaneously. But if your code is I/O-bound (waiting for a network response, file read, or DB query), threads are still useful because the GIL is released while a thread waits for I/O, letting other threads run.

How to work around it: Use multiprocessing for CPU-bound work — each process has its own Python interpreter and GIL, so you get true parallelism. Use asyncio for I/O-bound tasks with high concurrency. Or use PySpark to distribute work across multiple machines.

"At Citadel, our ML pipelines were CPU-intensive so we used PySpark — each executor runs in its own process, sidestepping the GIL entirely."

02Mutable vs Immutable types — what are they and why does it matter?+
Answer

Mutable objects (list, dict, set) can be modified in-place — you can add, remove, or change their contents and the object stays at the same memory address. Immutable objects (int, str, tuple, frozenset) cannot be changed after creation — any "modification" actually creates a brand-new object in memory.

Why this matters in practice: 1) Mutable default argument trap: def f(x=[]) is a classic bug — that [] is created once when the function is defined, not on each call, so every call shares and keeps modifying the same list. Fix: use None as default and create the list inside. 2) Dict keys and set members must be hashable, and only immutable types are hashable — so you can use a tuple as a dict key but not a list. 3) When you pass a mutable object (like a list) to a function, the function can modify the caller's data because both are referencing the same object in memory.

03Explain decorators. How do they work internally?+
Answer

A decorator is a function that takes another function as input, adds some extra behavior around it (like logging or timing), and returns the modified version. When you write @my_dec above def func(), Python is doing func = my_dec(func) behind the scenes — your original function is being "wrapped" inside the decorator.

How it works internally: The decorator defines an inner wrapper function that runs some code before/after calling the original function, then returns that wrapper. This relies on closures — the inner function "remembers" the original function from its enclosing scope.

Common use cases: Logging (log every function call), authentication checks, caching results (@functools.lru_cache), timing execution, retry logic on failures, and input validation. FastAPI's @app.get("/path") is itself a decorator that registers a function as an HTTP endpoint.

"At EY, I used decorators for request logging on FastAPI endpoints. I also used @lru_cache to cache expensive DB lookups in clinical pipelines."

04List comprehension vs Generator expression — difference?+
Answer

List comprehension [x for x in range(n)] builds the entire list in memory at once — if n is 10 million, all 10 million items sit in RAM. Generator expression (x for x in range(n)) produces values lazily, one at a time on demand — it uses almost no memory regardless of how many items it will produce.

When to use which: Use generators for large or streaming data where you only need to iterate once (reading huge files, feeding data into a pipeline). Use lists when you need random access (like items[5]), need to iterate multiple times, or the dataset is small enough that memory isn't a concern.

"In EY's healthcare pipelines, I used generator patterns for streaming CSV processing before passing to PySpark — avoiding loading full files into driver memory."

05How does Python memory management work?+
Answer

Python manages memory automatically using a private heap — you never allocate or free memory yourself. Two mechanisms handle cleanup:

1) Reference counting: Every object has a counter tracking how many variables point to it. When a variable is reassigned or goes out of scope, the count decreases. At zero, the object is freed immediately. This handles most garbage collection.

2) Garbage collector (gc module): Reference counting alone can't detect circular references (object A points to B, B points to A — both have count > 0 but neither is reachable). Python's GC uses generational collection with 3 generations — new objects are checked frequently, long-lived objects less often, since most garbage is short-lived.

Python also optimizes with small object pooling: Integers from -5 to 256 and common short strings are pre-created and reused (called "interning"), so a = 5; b = 5 point to the exact same object in memory.

06Explain *args and **kwargs+
Answer

*args lets a function accept any number of extra positional arguments — they get packed into a tuple. So def add(*args) called as add(1, 2, 3) gives args = (1, 2, 3). **kwargs does the same for keyword arguments — they get packed into a dict. So def config(**kwargs) called as config(host="localhost", port=8080) gives kwargs = {'host': 'localhost', 'port': 8080}.

Parameter order matters: def f(regular, *args, keyword_only, **kwargs) — regular params first, then *args, then keyword-only, then **kwargs.

Common real-world uses: Decorators need *args/**kwargs so the wrapper function can accept whatever arguments the original function takes. Also used for forwarding arguments to parent __init__ in inheritance, and building flexible API wrappers.

07Deep copy vs Shallow copy+
Answer

Shallow copy (copy.copy()) creates a new outer container, but the items inside still point to the same nested objects as the original. Think of it like copying a folder — you get a new folder, but the files inside are still the same files. So modifying a nested list inside the copy also affects the original.

Deep copy (copy.deepcopy()) recursively copies everything — the outer object and all nested objects at every level — producing a fully independent clone. Changes to the copy have zero effect on the original.

When it matters: For flat structures (a list of integers), shallow copy is perfectly fine and faster. But for nested structures (list of dicts, list of lists, config objects), you need deep copy if you want truly independent data. A classic interview trap is modifying a "copy" of a nested structure and being surprised the original changed too.

08What are generators and the yield keyword?+
Answer

A generator function looks like a normal function but uses yield instead of return. When you call it, it doesn't run the body immediately — it returns a generator iterator. Each time you ask for the next value (via next() or a for loop), execution runs until it hits yield, produces that value, and pauses — remembering exactly where it left off. The next call resumes from that exact spot.

Key benefit — lazy evaluation: A generator that can produce 10 million items uses the same tiny amount of memory as one that produces 10, because it only holds one value at a time. Perfect for reading huge files line-by-line, creating infinite sequences, or building data pipeline stages where each stage processes one item at a time and passes it along.

09How is Python's pass-by-assignment different from pass-by-reference/value?+
Answer

Python doesn't use traditional "pass-by-value" or "pass-by-reference" — it uses pass-by-object-reference. When you pass a variable to a function, the function gets a reference (a pointer) to the same object in memory — not a copy, and not a reference to the variable itself.

What happens next depends on mutability: If the object is mutable (list, dict), the function can modify it in-place and the caller sees the changes — because both are looking at the same object. If the object is immutable (int, str), any "modification" like x = x + 1 actually creates a brand-new object and rebinds the local variable to it — the original is untouched.

Simple way to remember: def f(x): x.append(1) changes the caller's list (in-place mutation). def f(x): x = x + 1 does NOT change the caller's integer (rebinding to a new object).

10What is the difference between == and is?+
Answer

== checks value equality — "do these two objects have the same data?" It calls the __eq__ method internally. is checks identity — "are these literally the same object in memory?" (same memory address).

Example: [1,2] == [1,2] → True (same contents). [1,2] is [1,2] → False (two separate list objects that happen to contain the same data).

Rule of thumb: Almost always use ==. Only use is for checking against singletons: x is None, x is True, x is False. Don't use is for numbers or strings — Python caches small integers (-5 to 256) so 256 is 256 may be True but 257 is 257 may be False, which can cause confusing bugs.

11What are Python virtual environments and why use them?+
Answer

A virtual environment is an isolated Python installation with its own set of packages, completely separate from your system Python and other projects. Without it, if Project A needs requests==2.28 and Project B needs requests==2.31, they'd conflict. Virtual environments solve this by giving each project its own sandbox.

How to create: python -m venv myenv (built-in) or conda create -n myenv (Conda — especially good for managing CUDA and scientific packages). Activate it, install what you need, and those packages exist only in that environment.

Reproducibility: Pin your exact versions in requirements.txt (via pip freeze) or pyproject.toml so anyone can recreate the same environment. This eliminates "works on my machine" issues.

"At Citadel, we containerized each ML service with Docker + pinned requirements. Locally I use conda for managing CUDA dependencies with PyTorch."

12What is the difference between a module, package, and library?+
Answer

Module: The simplest unit — a single .py file. When you write import utils, Python looks for utils.py.

Package: A folder containing multiple related modules, tied together by an __init__.py file. For example, a payments/ folder with stripe.py and paypal.py is a package — import as from payments import stripe.

Library: A collection of packages distributed together to solve a broader problem — NumPy, Pandas, Requests are all libraries you install via pip.

Framework: A library that dictates your app's structure — you write code that fits into its patterns. Django and FastAPI are frameworks; you follow their rules, not the other way around.

13Explain Python's scope rules (LEGB)+
Answer

When Python sees a variable name, it searches for it in this specific order: Local (inside the current function) → Enclosing (any outer function wrapping this one) → Global (top-level module scope) → Built-in (Python's built-in names like print, len). It stops at the first match. If not found anywhere, you get a NameError.

Key gotcha: Assigning to a variable inside a function always creates a new local variable, even if a global with the same name exists. To explicitly modify a global, use global x. To modify a variable from an enclosing function (in closures), use nonlocal x. Without these keywords, Python treats the assignment as creating a fresh local.

2. Object-Oriented Python

14What is self in Python? Why explicit?+
Answer

self is a reference to the current instance of a class. When you call obj.method(), Python automatically passes obj as the first argument — that's self. Unlike Java/C++ where this is hidden, Python makes it explicit in the method signature, following the Zen of Python: "Explicit is better than implicit." It's a naming convention — you could call it anything, but always use self.

Related: @classmethod receives cls (the class itself, not an instance) — great for alternative constructors like User.from_json(data). @staticmethod receives neither self nor cls — it's just a utility function that lives inside the class for organization.

15__init__ vs __new__ — what's the difference?+
Answer

Object creation in Python is a two-step process: __new__ is called first — it actually creates the blank instance and returns it. Then __init__ is called — it initializes that instance by setting attributes (like self.name = name).

In everyday code, you almost never touch __new__ — you just define __init__. You only override __new__ in special cases like implementing the Singleton pattern (ensuring only one instance exists) or when subclassing immutable types like str or int (because you can't modify them in __init__ — they're already frozen by then).

16Explain inheritance, multiple inheritance, and MRO+
Answer

Python supports multiple inheritance — a class can inherit from more than one parent. But this creates a question: if two parents have a method with the same name, which one gets called? That's what MRO (Method Resolution Order) answers — it's a fixed order Python follows to look up methods, calculated using the C3 linearization algorithm. You can check it with ClassName.__mro__.

The classic diamond problem occurs when two parents share a common grandparent — without MRO, the grandparent's method could be called twice or ambiguously. Python's MRO ensures each class appears only once in the chain, preventing duplicates. Important: super() follows the MRO order, not just the immediate parent — this is what makes cooperative multiple inheritance work correctly.

17What are @classmethod, @staticmethod, and instance methods?+
Answer

Instance method: The default. Takes self as first argument, meaning it can read and modify the specific instance's data (like self.name). This is what you use 90% of the time.

Class method: Decorated with @classmethod, takes cls as first argument. It operates on the class itself, not a specific instance. Most commonly used as alternative constructors — e.g., Date.from_string("2024-01-01") that parses a string and returns a new Date object.

Static method: Decorated with @staticmethod, takes neither self nor cls. It's just a regular utility function that logically belongs to the class but doesn't need access to instance or class data — like a helper math function inside a geometry class.

18What are dunder/magic methods? Name some common ones.+
Answer

Dunder (double-underscore) or "magic" methods are special methods that Python calls automatically behind the scenes when you use certain syntax or operations. You define them, but Python invokes them implicitly.

Common ones: __init__ — called when you create an object. __str__ — called by print() for a human-readable string. __repr__ — called in the debugger/REPL for a developer-friendly string. __len__ — powers len(obj). __getitem__ — powers obj[key] indexing. __eq__ — powers == comparison. __hash__ — makes objects usable as dict keys. __enter__/__exit__ — enables with statement (context manager). __iter__/__next__ — makes objects work in for loops. By implementing these, your custom classes can behave like built-in Python types.

19What are abstract classes and ABCs?+
Answer

An abstract class is like a blueprint or contract — it defines methods that any subclass must implement, but it doesn't implement them itself. You create one using from abc import ABC, abstractmethod. If a subclass forgets to implement an abstract method, Python raises an error when you try to create an instance.

You can't create an instance of an abstract class directly — it's meant to be inherited from, not used on its own.

Use case: Say you're building a payment system with Stripe, PayPal, and Square. You'd create an abstract PaymentProcessor class with abstract methods charge() and refund(). This guarantees every processor implements both methods — if someone adds a new processor and forgets refund(), Python catches it immediately.

20What are dataclasses? When would you use them?+
Answer

@dataclass (Python 3.7+) automatically generates __init__, __repr__, and __eq__ methods just from your class attributes with type hints. Instead of writing 15 lines of boilerplate __init__ code to assign self.name = name, self.age = age, etc., you just list the fields and Python handles the rest.

When to use: Whenever you need a class primarily for holding data — like a User, Config, or APIResponse. It keeps your code clean and readable. For immutable records (data that should never change after creation), use @dataclass(frozen=True) — which also makes instances hashable and usable as dict keys. NamedTuple is another lighter alternative for simple immutable records.

21What is @property and how does it work?+
Answer

@property lets you define a method that looks and feels like a simple attribute to the caller — they write user.age not user.get_age(). Behind the scenes, it's actually calling your method, where you can add validation, computation, or access control.

Why it's useful: You can start with a simple attribute (self.age = 25), and later add validation without breaking any code that uses it. For example: @property def age(self): return self._age and @age.setter def age(self, val): if val < 0: raise ValueError("Age can't be negative"). All existing code that does user.age = 30 still works — but now invalid values are caught. You can also create computed properties like full_name that combines first_name and last_name.

3. Python Data Structures & Collections

22List vs Tuple — when to choose which?+
Answer

List is mutable — you can add, remove, and change items after creation. Use lists for collections that grow, shrink, or change over time (a shopping cart, a queue of tasks, accumulating results).

Tuple is immutable — once created, it cannot be modified. Use tuples for fixed data that shouldn't change (GPS coordinates, database row results, RGB color values, returning multiple values from a function).

Practical differences: Because tuples are immutable, they can be used as dictionary keys and set members (lists cannot). Tuples are also slightly faster to create and iterate, and use less memory than equivalent lists. Python can also optimize tuples internally since it knows they won't change.

Quick rule: If the data represents a fixed record or structure → tuple. If it's a collection you'll modify → list.

23What is a dict? How does it work internally?+
Answer

A Python dict is implemented as a hash table. When you set d["name"] = "Alice", Python computes a hash of the key "name" (a number), uses that hash to determine a slot (bucket) in an internal array, and stores the key-value pair there. Looking up a key later uses the same hash to jump directly to the right slot — that's why get, set, and delete operations are all O(1) on average.

Keys must be hashable (immutable) because if a key's hash could change after insertion, Python would look in the wrong slot and never find it again. That's why you can use strings, numbers, and tuples as keys, but not lists or dicts.

Since Python 3.7+, dicts officially maintain insertion order — items come out in the order you put them in. Before 3.7, order was not guaranteed (you'd use OrderedDict for that).

Hash collisions (two different keys hashing to the same slot) are handled by open addressing — Python probes nearby slots to find an empty one. If too many slots are filled (high load factor), the table resizes by roughly doubling, and all entries are re-inserted.

24Set operations and when to use sets+
Answer

A set is an unordered collection of unique elements, also backed by a hash table (like dicts, but only keys, no values). Because of hashing, checking whether an element is in a set is O(1) — compared to O(n) for a list, which has to scan every element.

Set operations (like math sets): a & b (intersection — elements in both), a | b (union — elements in either), a - b (difference — elements in a but not b), a ^ b (symmetric difference — elements in one but not both).

When to use sets: Removing duplicates from a list (unique = list(set(my_list))), fast membership testing (converting a list to a set before checking if x in my_set is one of the most common Python optimizations), and performing set math operations on collections. Anytime you find yourself writing if item in some_list inside a loop, consider converting to a set first.

25What is collections.defaultdict?+
Answer

defaultdict is a dict subclass (from the collections module) that automatically provides a default value for any key that doesn't exist yet, so you never get a KeyError. You tell it what factory function to use when creating default values.

How it works: defaultdict(int) — missing keys default to 0 (since int() returns 0). defaultdict(list) — missing keys default to [] (since list() returns an empty list). defaultdict(set) — missing keys default to an empty set.

Why it's useful: Without it, counting words requires checking if word in d: d[word] += 1 else: d[word] = 1. With defaultdict(int), you just write d[word] += 1 — if the key doesn't exist, it's automatically initialized to 0 first. Similarly, grouping items becomes d[category].append(item) with no key-existence check needed.

"I use defaultdict constantly in Karat-style problems — grouping students by courses, counting badge accesses, aggregating domain visits."

26What is collections.Counter?+
Answer

Counter (from collections) is a specialized dict subclass designed specifically for counting things. You pass it any iterable, and it creates a dictionary where keys are the elements and values are their counts.

Example: Counter("banana") produces {'a': 3, 'n': 2, 'b': 1}. Counter(["red", "blue", "red"]) produces {'red': 2, 'blue': 1}.

Useful methods: most_common(n) returns the n most frequent elements as a sorted list of tuples — great for "top N" questions. You can add and subtract Counters together (combine counts or find differences). elements() returns an iterator over elements repeating each as many times as its count.

Common use cases: Word frequency analysis, character counting, finding the most/least common elements in a dataset, and comparing two collections to see what's different.

27What is collections.deque?+
Answer

deque (pronounced "deck") stands for double-ended queue — it supports efficient O(1) append and pop from both the left and right ends. A regular Python list is O(1) for append/pop at the right end, but O(n) for operations at the left end (insert(0, x) or pop(0)) because all other elements have to shift over.

When to use deque: Implementing a BFS queue (breadth-first search) — you append to the right and pop from the left, both O(1). Building a sliding window — add new elements to one end, remove old ones from the other. Maintaining a fixed-size history using deque(maxlen=100) — when the deque is full, adding a new item automatically drops the oldest one from the other end. This is much cleaner than manually managing a list.

28What is a namedtuple?+
Answer

A namedtuple is a tuple subclass that gives names to each position, so you can access elements by name instead of cryptic numeric indices. For example: Point = namedtuple('Point', ['x', 'y']), then p = Point(3, 7) lets you write p.x instead of p[0] — much more readable.

Like regular tuples, namedtuples are immutable (you can't change values after creation) and lightweight (they use less memory than a regular class because they don't have a per-instance __dict__). They're perfect for structured records where you want clarity without the overhead of a full class — things like database rows, coordinate pairs, or API response data.

Modern alternatives: typing.NamedTuple adds type hint support (class Point(NamedTuple): x: float; y: float), and @dataclass(frozen=True) provides similar immutability with more flexibility (methods, default values, etc.).

29Time complexity of common Python operations+
Answer

Knowing the time complexity of Python's built-in operations is critical for writing efficient code and acing interviews:

List: Index access a[i] is O(1). Append is O(1) amortized. Insert/delete at a specific position is O(n) because elements shift. Searching (if x in list) is O(n) — it scans every element. Sorting is O(n log n).

Dict: Get, set, and delete are all O(1) on average (thanks to hashing). Worst case is O(n) if every key hashes to the same bucket, but this almost never happens in practice. Iterating over all items is O(n).

Set: Add, remove, and membership testing (if x in set) are all O(1) on average. Union and intersection are O(m+n) where m and n are the sizes of the two sets.

deque: Append/pop from either end is O(1). But random index access (d[5]) is O(n) — unlike lists, deques aren't optimized for that.

The #1 interview optimization pattern: If you're checking membership inside a loop using a list, switch to a set or dict. This alone often converts an O(n²) solution to O(n).

4. Advanced Python Concepts

30Explain exception handling (try/except/else/finally)+
Answer

Python's exception handling has four parts that work together:

try: Wraps the "risky" code that might raise an exception. except ExceptionType as e: Catches and handles a specific type of error — you can have multiple except blocks for different error types. else: Runs only if no exception occurred in the try block — useful for code that should only execute on success. finally: Always runs, whether an exception happened or not — perfect for cleanup like closing files or database connections.

Best practices: Always catch specific exceptions (like ValueError, FileNotFoundError) rather than a bare except: which catches everything including keyboard interrupts and system exits. Create custom exception classes for your domain (e.g., class InsufficientFundsError(Exception)) to make error handling more meaningful and readable.

"At EY, I created custom exceptions like ClinicalDataValidationError with HTTP status mappings in FastAPI exception handlers."

31Multithreading vs Multiprocessing — when to use which?+
Answer

Threading (threading module): Multiple threads share the same memory space within one process. Great for I/O-bound tasks — while one thread waits for a network response or file read, another thread can run. However, due to the GIL, threads take turns executing Python code, so CPU-heavy work doesn't get faster with threads.

Multiprocessing (multiprocessing module): Spawns separate processes, each with its own Python interpreter and its own GIL. Achieves true parallelism on multiple CPU cores, making it ideal for CPU-bound work like ML training, image processing, or heavy data transformations. The trade-off is higher memory usage (each process has its own memory) and overhead for inter-process communication.

Third option — asyncio: Uses a single thread with an event loop to handle thousands of concurrent I/O operations. Instead of threads switching context, your code explicitly awaits I/O operations. Lower overhead than threading and excellent for high-concurrency scenarios like web servers and API gateways.

Quick decision guide: Waiting on I/O? → asyncio or threading. Crunching numbers? → multiprocessing or PySpark.

"At Citadel I used PySpark for CPU-heavy batch inference (multiprocessing across executors), and async/await in FastAPI services for non-blocking DB calls."

32What is asyncio and async/await?+
Answer

asyncio is Python's built-in framework for writing concurrent code using a single thread and an event loop. The event loop is like a traffic controller — it keeps track of all the tasks that are waiting for something (a network response, a database query, a file read) and efficiently switches between them.

async def defines a coroutine — a function that can be paused and resumed. await is where the magic happens: when you write data = await fetch_from_api(), execution pauses at that line, gives control back to the event loop (which can run other tasks), and resumes when the API response arrives.

Key insight: It's single-threaded but can handle thousands of concurrent connections because most of the time is spent waiting for I/O, not computing. While one request waits for a database response, the event loop can process hundreds of other requests.

Real-world use: FastAPI is built entirely on top of asyncio, which is a big reason it's so fast. Also great for microservices, web scraping (fetching many pages concurrently), chat applications, and any service that makes lots of external calls.

33What are context managers and the 'with' statement?+
Answer

Context managers handle setup and teardown automatically, guaranteeing cleanup happens even if an error occurs. The most familiar example is file handling: with open("file.txt") as f: — the file is opened when you enter the with block and automatically closed when you leave it, even if an exception is raised inside.

How they work internally: A context manager implements two dunder methods: __enter__ (runs at the start of the with block, returns the resource) and __exit__ (runs when leaving the block, handles cleanup and can suppress exceptions). Python calls these automatically.

Common uses beyond files: Database connections (auto-commit or rollback), thread locks (auto-release), temporary directories (auto-delete), timing code execution, and managing API sessions.

Easy way to create one: Use @contextmanager from contextlib — write a generator function with a single yield. Code before yield is the setup, code after is the teardown. This avoids writing a full class with __enter__ and __exit__.

34What are closures in Python?+
Answer

A closure is an inner function that remembers and has access to variables from its enclosing (outer) function's scope, even after the outer function has finished executing and returned. The inner function "closes over" those variables — hence the name.

Simple example: If you write a function make_multiplier(n) that defines and returns an inner function def multiply(x): return x * n, then double = make_multiplier(2) creates a closure where n=2 is captured. Calling double(5) returns 10, even though make_multiplier has already returned — the inner function remembers n.

Why closures matter: They are the fundamental mechanism behind decorators — the wrapper function is a closure that remembers the original function. They're also used for factory functions (creating customized functions on-the-fly), callbacks with state (passing context to event handlers), and data encapsulation (hiding variables from the outside world without using a class).

35What are lambda functions?+
Answer

Lambda functions are small, anonymous (nameless) functions defined in a single expression: lambda x: x * 2. They're meant for quick, throwaway operations where defining a full def function would be overkill.

Most common uses: Sorting with a custom key (sorted(users, key=lambda u: u.age)), quick transformations with map() and filter(), and pandas .apply() for column operations. They're limited to a single expression — no multi-line logic, no statements. If your logic is complex, use a regular named function instead for readability.

36What are type hints? Why use them?+
Answer

Type hints are optional annotations that tell developers (and tools) what types a function expects and returns: def greet(name: str) -> str:. Python does not enforce these at runtime — they're hints, not rules. You can still pass an int where str is expected and Python won't complain.

So why use them? IDEs like VS Code use them for smart autocompletion and error highlighting. Tools like mypy can statically analyze your code and catch type bugs before you even run it. They serve as self-documenting code — anyone reading the function signature immediately knows what it expects. In large codebases with many developers, type hints are essential for navigability.

Bonus: FastAPI uses type hints for automatic request validation — if you annotate a parameter as int, FastAPI validates incoming data and returns a 422 error if it gets a string.

37What is the walrus operator (:=)?+
Answer

The walrus operator := (Python 3.8+) assigns a value to a variable and returns it in the same expression. Normally, assignment (n = len(a)) and comparison (if n > 10) are two separate lines. The walrus lets you combine them: if (n := len(a)) > 10: print(n) — it assigns len(a) to n and checks the condition in one shot.

Best use cases: While loops that read input — while (line := f.readline()) reads a line and checks if it's empty in one step. List comprehensions where you'd otherwise compute the same value twice — [y for x in data if (y := expensive(x)) > threshold] computes expensive(x) once and reuses it.

38What are iterators and the iterator protocol?+
Answer

An iterator is any object that produces values one at a time. It implements two methods: __iter__() (returns itself) and __next__() (returns the next value, or raises StopIteration when exhausted).

How for loops actually work: When you write for x in something, Python first calls iter(something) to get an iterator, then repeatedly calls next() on it until StopIteration is raised. So lists, strings, dicts — they're all "iterable" because they can produce an iterator.

Every generator is automatically an iterator. You can also make any custom class iterable by implementing __iter__ and __next__ — for example, creating a custom range-like class or a paginated API reader.

39What are slots and when would you use them?+
Answer

Normally, every Python object has a __dict__ — a dictionary storing all its attributes. Dictionaries are flexible but use a lot of memory. __slots__ replaces that dictionary with a fixed-size array by declaring upfront exactly which attributes the class will have: __slots__ = ['name', 'age'].

Benefits: ~40% less memory per instance and slightly faster attribute access. The tradeoff: you can't add attributes dynamically — only the ones listed in __slots__ are allowed.

When to use: When you're creating millions of small objects (like nodes in a graph, pixels, or data records) and memory savings add up significantly. Not worth the trouble for regular classes with few instances.

40What is monkey patching?+
Answer

Monkey patching means modifying a class, module, or function at runtime — after it's already been defined. For example, you could replace a method on a third-party library's class to fix a bug, without touching its source code. You just reassign: SomeLibrary.broken_method = my_fixed_version.

Why it's dangerous: Other parts of the code expect the original behavior, so monkey patches can cause confusing bugs that are hard to trace. The modification is invisible in the source code — you have to know it happened at runtime.

Where it's acceptable: Testing — Python's unittest.mock.patch is basically structured monkey patching. You temporarily replace a real database call with a fake one during tests, then restore the original after. This is clean and expected.

5. Performance & Optimization

41How do you profile Python code?+
Answer

Tools available: cProfile is built-in — it shows you how many times each function was called and how long it took, helping you find the slow spots. timeit is for micro-benchmarking a specific snippet (e.g., comparing two approaches). line_profiler goes deeper — it shows execution time for each individual line. memory_profiler shows memory usage per line, useful for finding memory leaks.

The right workflow: Don't guess what's slow — profile first → identify the actual hotspot (usually 1-2 functions cause 80% of the slowness) → optimize only those → re-profile to verify the improvement. Premature optimization without profiling wastes time on code that doesn't matter.

42Common Python performance pitfalls?+
Answer

1) String += in loops: Strings are immutable, so each += creates a new string and copies everything — O(n²). Fix: collect in a list, then "".join(parts).

2) in on lists instead of sets: Searching a list is O(n); searching a set is O(1). Inside a loop, this difference turns O(n) into O(n²).

3) Nested loops when a hash map would work: Two nested loops over the same data is O(n²). Often you can build a dict in O(n) first, then do O(1) lookups.

4) Loading entire files into memory: Use generators or iterate line-by-line instead.

5) Python loops for numerical work: NumPy vectorized operations are 10-100x faster because they run in C.

6) Not using built-ins: Functions like sum(), min(), sorted() are implemented in C and faster than hand-written Python loops.

43What is functools.lru_cache?+
Answer

@lru_cache is a built-in decorator that remembers previous function results — if you call the function again with the same arguments, it returns the cached result instantly instead of recomputing. This technique is called memoization.

LRU stands for "Least Recently Used" — when the cache is full (maxsize=128 by default), it evicts the result that hasn't been used for the longest time.

Biggest impact: Recursive functions. A naive fibonacci implementation is O(2^n) — with @lru_cache, it becomes O(n) because each value is computed once and cached. Also great for caching expensive DB queries or API calls in data pipelines.

Requirement: All function arguments must be hashable (no lists or dicts — use tuples instead).

44When would you use NumPy over pure Python?+
Answer

NumPy stores data in contiguous C arrays (not Python objects), and performs operations in compiled C code — this enables vectorized operations where an entire array is processed in one go, completely bypassing Python's slow loop overhead. The result: 10-100x faster than equivalent pure Python code for numerical work.

Example: Multiplying every element in a list by 2 — a Python loop iterates one by one, but np.array * 2 does it all at once in C. The bigger the data, the bigger the speedup.

Use for: Matrix math, statistical operations (mean, std, percentiles), any batch numeric processing. In ML pipelines, all feature engineering should use NumPy/Pandas vectorization — never Python for-loops over data rows.

JOB-CRITICAL

7. GenAI, LLMs & Machine Learning

49What is RAG (Retrieval-Augmented Generation)? How did you implement it?+
Answer

RAG solves a core LLM limitation: LLMs can only answer from what they were trained on, which can be outdated or missing your private data. RAG fixes this by retrieving relevant documents first, then feeding them as context to the LLM so it generates answers grounded in actual, up-to-date information — rather than hallucinating.

How the pipeline works: 1) User asks a question → 2) The question is converted to an embedding (a numerical vector) → 3) That vector is used to search a vector database (ChromaDB, FAISS, Pinecone) for the most similar document chunks → 4) The top-k most relevant chunks are injected into the LLM's prompt as context → 5) The LLM generates an answer using that context, with source attribution.

Key benefit over fine-tuning: When your data changes, you just update the vector DB — no expensive model retraining needed.

"At Citadel, I prototyped a RAG system using LangChain + Vector DB + OpenAI. I chunked internal docs with overlap, embedded with OpenAI embeddings, stored in a vector store. The LLM answered enterprise questions with sourced references."

50Fine-tuning vs RAG — when to choose which?+
Answer

Fine-tuning modifies the model's internal weights by training it on your specific data. It changes how the model thinks and responds — its style, tone, and domain expertise become baked in. Downsides: expensive compute, needs labeled training data, and you must retrain every time data changes.

RAG keeps the base model as-is and injects external knowledge at query time. Think of it as giving the model a "cheat sheet" of relevant documents for each question. Cheaper, dynamically updated (just update the vector DB), and provides source attribution (you know where each answer came from).

When to choose which: Fine-tuning for changing the model's behavior/style or teaching it domain-specific language (like medical terminology). RAG for keeping answers up-to-date with frequently changing knowledge, when source citations matter, or for data privacy (your docs stay in your DB, not baked into a model). LoRA/QLoRA are parameter-efficient fine-tuning techniques that train small adapter layers instead of the full model — dramatically cheaper (90%+ less compute).

51Explain prompt engineering techniques+
Answer

Prompt engineering is the art of crafting LLM inputs to get the desired output. Since LLMs are sensitive to how you ask, small changes in phrasing can dramatically improve results.

Key techniques: 1) System prompts — set the model's role and context ("You are a medical assistant. Be precise and cite sources."). 2) Few-shot examples — show the model 2-3 input→output examples so it learns the pattern you want. 3) Chain-of-thought — ask the model to "think step by step," which dramatically improves reasoning accuracy. 4) Output constraints — specify format ("Respond in JSON", "Only answer from the provided context", "Keep it under 100 words"). 5) Temperature tuning — lower temperature (0.0-0.3) for consistent, factual responses; higher (0.7-1.0) for creative, varied outputs.

"In our RAG system, I designed prompts instructing the LLM to only answer from retrieved context and cite source documents — reducing hallucinations significantly."

52What is LangChain and why use it?+
Answer

LangChain is a Python framework that makes it easier to build complex LLM-powered applications by providing reusable building blocks:

Chains: Connect multiple LLM calls in sequence — e.g., first summarize a document, then translate the summary. Agents: LLMs that can dynamically decide which tools to use (search the web, query a DB, run code) based on the user's question. Retrieval: Built-in integration with vector stores for RAG pipelines. Memory: Maintains conversation context across multiple exchanges so the LLM remembers what was said earlier.

Biggest advantage: Provider abstraction — you can swap between OpenAI, Anthropic, or open-source models without rewriting your application logic. This prevents vendor lock-in.

"I used LangChain's RetrievalQA chains at Citadel and LangChain agents in my Agentic Medical Intelligence project for multi-tool orchestration."

53What are vector databases and embeddings?+
Answer

Embeddings are numerical representations (vectors of hundreds of numbers) that capture the meaning of text. The key insight: texts with similar meanings end up close together in vector space. So "happy dog" and "joyful puppy" would have nearby vectors, even though they share no words. Generated by specialized models like OpenAI's embedding models or open-source sentence-transformers.

Vector databases (FAISS, ChromaDB, Pinecone, Weaviate) are purpose-built to store these vectors and find the most similar ones quickly using techniques like cosine similarity and approximate nearest neighbor (ANN) search. They're the backbone of RAG systems — when a user asks a question, the question is embedded and the vector DB finds the most relevant document chunks by similarity. They also store metadata alongside vectors (source URL, page number, etc.) for traceability.

54What are Transformers? How do attention mechanisms work?+
Answer

Transformers are the architecture behind GPT, BERT, and virtually every modern LLM. Unlike older RNNs that process words one-by-one in order, Transformers process all words in parallel — making them much faster to train.

Core innovation — self-attention: For each word in a sentence, the model asks "which other words in this sentence are most relevant to understanding me?" For example, in "The cat sat on the mat because it was tired," attention helps the model link "it" back to "cat." This is computed using Q (query), K (key), V (value) matrices that calculate relevance scores between all word pairs.

Multi-head attention: Instead of one attention calculation, the model runs several in parallel — each "head" can learn different types of relationships (grammar, meaning, context).

Two architectures: Encoder (BERT-style) — sees all words at once (bidirectional), best for understanding tasks like classification and search. Decoder (GPT-style) — generates one word at a time (autoregressive), best for text generation.

Key components: Pre-trained models + tokenizers for every major architecture (BERT, GPT, T5, LLaMA). The datasets library for easy access to thousands of datasets. accelerate for distributed training across multiple GPUs. Model hosting via their Inference API for deploying models without managing infrastructure.

Why it matters: It democratized ML — you don't need to train models from scratch anymore. Most new research papers release their models on Hugging Face, making cutting-edge AI accessible to everyone.

58What is Agentic AI?+

Agentic AI goes beyond simple chat — these are AI systems that can autonomously plan, execute multi-step tasks, use tools, and adapt based on results. 59Explain feature engineering in ML pipelines+
Answer

Feature engineering is the process of transforming raw data into meaningful inputs that help ML models make better predictions. It's often the difference between a mediocre model and a great one — "garbage in, garbage out."

Key techniques: Encoding categoricals — converting text categories to numbers (one-hot encoding for few categories, label encoding for ordinal data). Scaling numerics — normalizing values so all features are on a similar scale (StandardScaler for normal distributions, MinMaxScaler for bounded ranges). Creating interaction features — combining existing features (e.g., price × quantity = total). Handling missing values — imputation with mean/median/mode, or creating a "is_missing" flag. Text vectorization — converting text to numbers via TF-IDF or embeddings. Time-based features — extracting day-of-week, hour, lag features, rolling averages from timestamps.

60PyTorch vs TensorFlow — differences and when to use each?+
Answer

PyTorch: Uses dynamic computation graphs (define-by-run) — the graph is built on-the-fly as your code executes, making it feel natural and Pythonic. Easy to debug with standard Python tools. Dominant in research and GenAI because of its flexibility.

TensorFlow: Originally used static graphs (define-and-run — you build the entire graph first, then execute it), though TF 2.0 added eager mode. Historically stronger for production deployment and mobile/edge with TensorFlow Lite and TensorFlow Serving.

Current landscape: PyTorch has become dominant in both research and increasingly in production. The vast majority of Hugging Face models are PyTorch-first. TensorFlow is still used heavily in large companies with existing TF infrastructure. Practical advice: Use whichever the team/company uses — the concepts transfer between them.

9. Code Analysis / "What's Wrong?" Questions

66Bug: def append_to(item, target=[])+
Answer

Bug: Mutable default argument. The [] is created only once — when the function is defined, not each time it's called. So every call to the function that doesn't pass target shares and keeps appending to the same list. Call it 3 times and that list has 3 items, even though you expected a fresh empty list each time.

Fix: Use None as the default and create the list inside: def append_to(item, target=None): if target is None: target = []. Now a new list is created on every call. This is the most common Python interview gotcha — shows you understand how default arguments work.

67Performance: string += in a loop+
Answer

The problem: Strings are immutable in Python — every time you do result += new_piece, Python creates an entirely new string and copies all the old content plus the new piece into it. On the first iteration it copies 1 character, then 2, then 3… After n iterations, you've copied roughly n²/2 characters total — that's O(n²).

The fix: Collect pieces in a list (parts.append(new_piece)), then join at the end with "".join(parts). Lists are mutable so appending is O(1), and join allocates one final string of the right size — total O(n). For large strings (building HTML, logs, CSVs), this difference is massive.

68Performance: "if x in my_list" inside a loop+
Answer

The problem: Checking if x in my_list scans the list element by element — O(n). If you're doing this inside a loop of m items, you're scanning the list m times — O(m × n). With large datasets, this is extremely slow.

The fix: Convert the list to a set once: my_set = set(my_list) — O(n) one-time cost. Then if x in my_set is O(1) hash lookup on every iteration. Total: O(m + n) instead of O(m × n).

This is the #1 optimization pattern in coding interviews. Whenever you see a loop doing lookups or membership checks, converting to a set/dict is almost always the answer.

69What does this print? x=[1,2,3]; y=x; y.append(4); print(x)+
Answer

It prints [1, 2, 3, 4]. When you write y = x, you're NOT creating a copy — you're creating a second name (alias) that points to the exact same list object in memory. So when you y.append(4), you're modifying the one and only list, and both x and y see the change.

Fix: If you want an independent copy, use y = x.copy() or y = x[:] (slice notation) or y = list(x). For nested structures (list of lists), you need copy.deepcopy(x) for a fully independent clone.

70Bug: late binding closure in loop+
Answer

The surprise: funcs = [lambda: i for i in range(5)] creates 5 lambda functions, but calling any of them returns 4 — they ALL return 4, not 0,1,2,3,4 as you might expect.

Why: Closures capture variables by reference, not by value. All 5 lambdas share a reference to the same variable i. By the time you actually call any of them, the loop has finished and i equals 4 — so they all return 4.

Fix: Use a default argument to capture the current value at each iteration: lambda i=i: i. Default arguments are evaluated at function definition time (during each loop iteration), so each lambda gets its own frozen copy of i.

71What's wrong: except Exception: pass+
Answer

This is a "silent failure" anti-pattern. It catches every possible exception — including real bugs like TypeError, NameError, even KeyboardInterrupt — and does absolutely nothing. The error disappears without a trace, making debugging a nightmare because bugs are completely hidden.

Why it's terrible: Imagine a database connection fails silently, and your app continues running with stale data for days before anyone notices. Or a calculation returns wrong results because a division by zero was swallowed.

How to fix: 1) Always catch specific exception types (except ValueError, not bare except). 2) At minimum, log the exception (logging.error(f"Failed: {e}")). 3) Handle the error appropriately — retry, return a default, or re-raise. The Zen of Python says it best: "Errors should never pass silently."

72Performance: repeatedly calling len() in a loop condition+
Answer

Trick question — this is NOT actually a performance issue in Python! Unlike languages like C where calculating string length requires scanning the entire string, Python stores the length as a pre-computed attribute on every list, string, and dict object. So len() is always O(1) — it just looks up the stored number, no matter how large the collection.

Why this matters in interviews: If someone "optimizes" this by caching n = len(my_list) before the loop, they're adding unnecessary complexity for zero performance gain. Knowing this shows depth of understanding about Python internals — you know what's truly slow vs. what just looks slow based on intuition from other languages.

73What does "import this" output?+
Answer

Running import this in Python prints the Zen of Python — 19 guiding principles that reflect Python's design philosophy, written by Tim Peters. The most important ones to know:

"Explicit is better than implicit" — don't hide what your code does (this is why Python has self). "Simple is better than complex" — choose the straightforward approach. "Readability counts" — code is read far more often than it's written. "Errors should never pass silently" — never use bare except: pass. "There should be one — and preferably only one — obvious way to do it" — Python prefers one clear way over multiple confusing alternatives. These principles are a fun Easter egg but also genuinely guide Python's design decisions.
